# Bonsai 2 27B · 一键运行版（给好奇的小白）

在**一张 12GB 显存的 N 卡**上，本地跑一个 27B 大模型，支持 **26 万字超长上下文**，
带浏览器聊天界面。不用装 Python、不用装 CUDA、不用命令行。

---

## 一、你需要什么

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| 显卡 | **NVIDIA RTX 30 / 40 / 50 系**，显存 **≥ 12GB** |
| 内存 | **≥ 16GB**（推荐 32GB；见下方说明） |
| 驱动 | 较新的官方驱动（支持 CUDA 13.2） |
| 磁盘 | 至少 **13GB** 空闲 |
| 网络 | 第一次运行要下载约 **10.5GB**（之后不再需要） |

**关于内存**（实测，100K 上下文满载）：

| 内存 | 结果 |
|---|---|
| 8 GB | 跑不了 |
| 16 GB | 能跑，但超长上下文会用到页面文件，可能变卡 |
| **32 GB** | **推荐，舒服** |

引擎满载时占约 10 GB 物理内存、提交峰值约 19 GB（大头是"记忆池"：
长上下文放不下显存时，读过的内容挪到内存备用）。脚本会**按你的内存自动调这个池子的大小**：
32GB 以上给 12GB，24GB 左右给 10GB，16GB 给 6GB，更少给 4GB。

**能跑的卡**：RTX 3060 12G、4070 Ti Super 16G、4080、4090、5070 及以上。
**跑不了的卡**：显存 8G 及以下（3060 Ti / 4060 / 3070 等），或者 AMD / Intel / 核显。

> 先别急着下 10GB：想先确认能不能跑，双击 `START.bat` 后它会**先检查环境**，
> 不满足会立刻告诉你，不会白下。

---

## 二、怎么用

1. **双击 `START.bat`**
2. 第一次会依次：检查显卡 → 下载引擎（约 1GB）→ 下载模型（8.87GB）→ 启动
   - 下载看网速，可能 30~60 分钟。**中途断了没关系，再双击一次会自动续传。**
3. 启动完成后，**浏览器会自动打开聊天界面**，直接打字聊天

**停止**：双击 `STOP.bat`。

**卸载**：直接删掉整个文件夹（它不会往系统别处写东西）。

## 三、你能得到什么

在 RTX 3060 12G 上实测（这就是这个包用的配置）：

| | 数值 |
|---|---|
| 上下文 | **262,144 字**（26 万字，一整个代码库塞得下） |
| 读提示词 | 约 **730 字/秒** |
| 写回答 | 散文约 35 字/秒，代码/工具类中位数 **60 字/秒** |
| 长文召回 | 26 万字里埋的标记，逐字答对 |
| 显存占用 | 约 11GB / 12GB |
| 视觉 | 支持看图（图片拖进聊天框即可） |

用法小贴士：**同一个任务接着聊**最快 —— 第一次读完整个上下文后，
后面每次追问只要 1~3 秒就出字（复用已读过的内容）。

### 3.1 首字慢？先看"思考预算"这一个旋钮

这个包默认 `--default-thinking-budget 8192`：模型在回答前最多可以先想 8,192 个 token。
在长上下文 + 难问题上，这 8K 思考会**全部发生在你看到第一个字之前**，按 60 字/秒算就是
**两分钟起步的沉默**。

本包自带一份 `chat-template-bonsai2.jinja`（与制品内的模板一致，只把**默认思考档位**从
`xhigh` 改成 `low`），启动时用 `--chat-template` 交给引擎：于是默认就"简短思考"，
界面里手动选档位仍然优先。想改回默认档位，删掉 `setup.ps1` 里那两行即可。

想更快就把 `setup.ps1` 里的 `--default-thinking-budget` 调小（`2048` 就明显快），
想让它多想就调大。调这一个数字就能换手感，不用改别的。

> 我们的生产实测（同一张 3060 12G、同一份制品、53,320 token 的真实流量、3 轮平均）：
> 思考预算从"默认最高档 + 24K 预算"改成"低档 + 封顶 8,192"之后，
> **正文从 0 token 变成 630 token**（原来思考把输出预算烧光了，答案一个字都没出来），
> 墙钟 84.2 → 75.3 秒，解码 59 → 174 tok/s。
> 配套的 280 题质量门：77.5% vs 76.4%，净 +3 题，p = 0.701（质量中性）。
> 详见 `docs/maintainer/execution-order-2026-10-20.md`。

### 3.2 2026-10-20 补充实测（本机，KVMem RC3 官方包 + 我们的自建引擎）

| 场景 | 提示 | decode | prefill | 备注 |
|---|---:|---:|---:|---|
| 生产配方（MTP 4 + ngram 31） | 3.4K | 73.6 tok/s | 905 tok/s | 思考默认档 |
| 生产配方 | 53,320 | 65.6 tok/s | 770 tok/s | 真实流量形状，首字 69 s |
| 我们的自建引擎（DFlash2 7 草稿） | 3.4K | **200.5 tok/s** | ~700 tok/s | 接受率 96.2% / 99.7% / 98.5% |
| 我们的自建引擎（DFlash2 7 草稿） | 53,320 | **64.5 tok/s** | 512 tok/s | 需引擎侧一处修复，见维护者文档 |

> DFlash2 目前**不在本包使用的引擎里**：KVMem worker 只放行 MTP 与 ngram 两种投机后端。
> 我们已把需求与复现步骤写进 `docs/maintainer/kvmem-dflash2-request-2026-10-20.md`。

## 四、出问题了

| 现象 | 原因 / 办法 |
|---|---|
| 提示"没找到 nvidia-smi" | 没装 N 卡驱动，或不是 N 卡 |
| 提示"显存不够" | 你的卡不到 12GB，换卡或换更小的模型 |
| 下载中断 | 再双击一次 `START.bat`，会从断点续传 |
| 启动很慢（1~3 分钟） | 正常，第一次要热身；之后就快了 |
| 引擎起不来 | 看窗口里打印的日志；常见是驱动太旧、显存被别的程序占着 |
| 聊天没反应 | 确认 `STOP.bat` 没被误点；重开一次 `START.bat` |

## 五、这里面是什么

- **模型**：Ternary Bonsai 2 27B（1.58 比特三元量化，底座 Qwen3.8-27B）
- **引擎**：KVMem NInfer（小显存跑长上下文的关键 —— 显存放不下时，
  把读过的内容挪到内存，用的时候按需取回）
- **本文件夹里的脚本**：由本项目的作者编写，只负责"检查环境 + 下载 + 启动"

所有大文件（引擎、模型）都是**运行时从官方源下载**的，本包不重新分发它们：

- 引擎：<https://github.com/kvmem/kvmem/releases> （Apache-2.0，内含 NVIDIA cuBLAS 运行库，受 CUDA EULA 约束）
- 模型：<https://huggingface.co/WaveCut/Ternary-Bonsai-2-27B-NInfer-v3>

作者实测记录与全部数据：见本仓库 `docs/maintainer/`。
